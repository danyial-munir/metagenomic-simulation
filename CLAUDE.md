Project guide for Claude. Read this fully before doing anything. It records the exam context, the fixed decisions,

## 1. What this project is

University exam project for **Statistical Data Analysis for Applied Physics**. Topic approved by the professors:
*Simulation of metagenomic data (relative abundances) to study seasonal dynamics of bacterial populations*, adapted to a
human skin (belly-button) microbiome dataset. The data has **no time dimension**, so the seasonal driver is **simulated**.

Deliverables:
1. **Literature review** (about 4–6 pages, verified references only), in `literature/`.
2. **Notebook(s)** with the whole analysis: commented, repeatable (fixed seed), runs top to bottom with "Restart and Run All".
3. **Report** (about 15–25 pages, clear academic English), in `report/`.
4. **Concept sheet** (`concept_sheet.md`) for the oral defence.

Evaluation is an **oral discussion with two professors**. They judge the work *and* whether the student understands the
basic concepts. **Everything built must be explainable by the student.** Prefer clear, standard methods and always
explain the reasoning behind a choice. The project is meant to be **visual**: strong, consistent figures matter.

The student codes in **Python**. No hard deadline; target about 3–4 weeks of work.

### Research questions
- **RQ1 (modelling):** which generative model for compositional count data best reproduces the real skin microbiome
  (sparsity, overdispersion, diversity, between-sample dissimilarity), and how do covariates (age, sex, washing
  frequency, navel type) enter it?
- **RQ2 (validation):** how closely does data simulated from the fitted model match the real data, with what uncertainty (bootstrap)?
- **RQ3 (seasonal scenario):** if a seasonal driver changes the abundance of some taxa by effect size A, how large must A
  be and how many samples are needed before standard tools detect it? (power analysis)

### Honesty about the seasonal signal (must appear in report and oral)
The seasonal signal is **imposed by simulation**, not estimated from data. The study answers "what would we be able to
detect if…", never "what is the seasonality of belly-button bacteria". Months are assigned to subjects at random
(each subject is sampled once; design is cross-sectional). State this as a limitation wherever relevant.

  ending with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## 5. The data (verified facts — do not re-derive)

Source is probably the belly-button microbiome study (Hulcr et al., "A jungle in there", PLoS ONE 2012), **but this has
not been verified**: the file has 273 subjects, while I recall that study as having about 60 participants (sample IDs
`YWL…`/`CALS…` suggest citizen-science and NC State cohorts). Check provenance in the literature step before citing.

**`taxonomy.csv`**
- 7 taxonomy columns (`Kingdom/Domain, Phylum, Class, Order, Family, Genus, Family_Genus`) then 273 sample columns.
- **Real table = 649 taxa rows**, file lines 2–650. It ends at the first row with an empty Kingdom cell. After it comes
  junk: a richness row (integers; exactly the observed taxa per sample, 273/273), a repeated header, a row of taxon
  names, a sparse row of 18 decimals, a stray note. The side table does **not** explain missing mass; treated as junk.
- Values use a **decimal comma** and are **fractions of 1000 reads**. Every value × 1000 is an integer; smallest
  non-zero value 0.001. The data are **rarefied to 1000 reads**, so exact integer counts are recovered (`to_counts`).
- The "median column sum ≈ 31" in the original brief came from including the richness row (1 + ~30).
- **Missing mass:** 48 samples sum to < 0.99, 7 to < 0.8, minimum 0.282 (sample 1306). Decision: add an explicit
  **`Unassigned` = 1000 − assigned** category so every sample is a full multinomial of 1000 reads. Sensitivity to run
  later: drop samples with < 80 % assigned. Richness correlates with assigned reads (Spearman −0.69); hypothesis (unverified)
  that the source dropped rare taxa.
- Rank values `Other` and an empty `x__` both mean "unresolved at this rank". Each row is labelled by its **deepest
  resolved rank** (`Family;Genus` when the genus is known, else `<name> (unresolved below <rank>)`), rows with equal
  label are summed: 649 rows → 585 labels (+ `Unassigned`). Only 64 % of reads have a resolved genus. Labels such as
  `Staphylococcaceae (unresolved below family)` are **bins, not single taxa** — say so in the report.
- 93 % zeros (all labels), 70.9 % zeros after the filter below.

**Analysis matrix** (`data/processed/counts_filtered.csv`): taxa with prevalence ≥ **10 %** of samples (112 taxa) +
`Other` + `Unassigned` = 114 categories, each row sums to 1000. The 10 % rule was fixed before modelling;
`filter_sensitivity.csv` covers 2 %–30 %. `counts_all_labels.csv` keeps every label.
Diversity/distances use the 113 categories without `Unassigned`.

**`environment.csv`** → `metadata.csv` (columns kept: `Gender, Age, Wash_Freq, Wash_Group, Navel, Ethnicity, In_NC`,
plus `assigned_reads`; ID index as string)
- 273/273 IDs match the taxonomy file. `Reads = 1000` for all (dropped). `Unknown` → NaN, **no imputation**; `0` washes per
  week is a real value, not missing. Full log in `data/processed/decision_table_env.csv`.
- Missingness (raw): `Wash_Freq` 42.5 % (a **block**, not random), Navel 13 %, Ethnicity 12.5 %, Age 10 %, Gender 3 %.
  ZIP/country-by-age columns > 90 % missing → dropped; `Current ZIPcode` 75 % missing and partly corrupt → dropped.
- `Wash_Range` contradicts `Wash_Freq` in 2 rows → `Wash_Freq` is the reference; `Wash_Group` is derived from it.
- Ethnicity groups with n < 10 merged (`Other`); only `In_NC` kept from geography. `Age_group` (0–18, 19–35, 36+) is built
  in the EDA notebook.
- Complete cases on (Age, Gender, Wash_Freq, Navel): 132. Models using Wash_Freq therefore use roughly 132–157 subjects
  and a non-random subset; always report n and compare with the model without Wash_Freq.

### Key EDA findings that drive the models
- **Strong overdispersion:** Taylor slope b = 1.84 (bootstrap 95 % CI 1.82–1.89; multinomial = 1). Every taxon has > 2× the
  multinomial variance, median ≈ 22× (IQR 7–94×). M0 is expected to fail; the benchmark is whether M1/M3 capture this.
- Dominance: Corynebacterium mean 23 %, a Staphylococcaceae bin 19.5 %; top-10 taxa = 66 % of reads; median sample has 42 % of
  reads in one taxon. Median Shannon 1.91, median richness 30, median Bray–Curtis between samples 0.79.
- Covariates explain little: PERMANOVA R² 0.4–3 %, strongest for age group and `In_NC`; wash frequency shows nothing.
  Expect covariate effects in M2 to be small; do not oversell them.
- Aitchison PCoA shows an arch (horseshoe) distortion, not a second biological signal.

### Phase 2 decisions and results (done)
- **Modelling resolution = top 20 taxa + `Other` + `Unassigned` (D = 22)**, file `data/processed/counts_top20.csv`
  (decision taken with the user). Reason: M3's likelihood needs a Laplace approximation; at D = 114 Laplace and importance
  sampling (IS) disagree (median 0.9, max 2.5 nats, IS ESS ≈ 5 of 20 000), at D = 22 they agree (median 0.13, max 0.25 nats,
  ESS > 2000). The 20 taxa carry 78.7 % of reads. **Phases 3 and 4 also work at D = 22**; seasonal taxa come from the top 20.
  M0 vs M1 are additionally reported at full resolution (114 categories, exact likelihoods).
- ALR reference = `Other` (most prevalent, 99.6 %), placed as the LAST column. Code convention in `src/models.py`.
- M3 fit: approximate EM with a Laplace E-step, Σ shrunk towards its diagonal; held-out M3 log-likelihood uses IS (10 000 draws).
  An ELBO lower bound with the Laplace Gaussian was tried and dropped (too loose, high MC error).
- **5-fold CV (held-out log-lik per sample, paired SE):** M0 −1074, M1 −65.3, **M3 (λ = 0.05) −58.0; M3 − M1 = +7.3 ± 0.3 nats,
  M3 better for 91 % of samples.** λ grid 0.005–0.7, curve flat for λ ≤ 0.1 (optimum interior). Min IS ESS on held-out samples 28.
- M1: A = 4.82 (95 % CI 4.40–5.35), ρ = 0.172 → variance ×173 vs multinomial; empirical ratio per category ranges 34–821 → one
  common ρ cannot fit; this motivates M3.
- **M2 (DM regression, covariates on top 10 taxa):** M2a (age, sex, navel; n = 217): LR = 82 on 30 df (p < 1e-4), ΔAIC = −22,
  ΔBIC = +79, **CV gain 0.04 ± 0.06 nats (none)**. M2b (+ wash frequency; n = 132): LR p = 0.0008, ΔAIC +6, CV −0.12 ± 0.10.
  8 of 30 bootstrap CIs exclude 1 (1.5 expected by chance); outie effects rest on only 16 outies. Conclusion: covariate effects
  are detectable in-sample but too small to improve prediction → **final simulator need not include covariates**.
- Saved for later phases: `model_params.npz` (columns, p0, alpha, mu, Sigma, shrink, M2a theta and covariate scaling),
  `model_comparison.csv`, `model_comparison_full_resolution.csv`, `model_m2_tests.csv`, `model_m2_coefficients.csv`,
  `model_laplace_check.csv`.

## 7. Plan for the remaining phases (analysis decisions already made)

**Phase 3 — validation.** Simulate datasets with the real design; compare sparsity, richness/Shannon distributions, per-taxon
prevalence and mean–variance, Bray–Curtis distribution, PCoA overlay. Parametric bootstrap and non-parametric bootstrap over
samples for CIs; KS/Wasserstein for distributions; PERMANOVA real vs simulated. Pick the final model with a written argument.

**Phase 4 — seasonal scenario.** Driver `s(t) = cos(2π(month − φ)/12)`, optionally simulated temperature
`T = seasonal sine + noise`. Perturb the log-ratio abundance of K taxa by amplitude A. Vary A, n, K, depth, baseline
overdispersion. Tools: PERMANOVA (Bray–Curtis and Aitchison) with season/month; per-taxon cosinor regression on CLR
(pseudocount 0.5, sensitivity checked) with Benjamini–Hochberg FDR. Report **type I error at A = 0 (must be ≈ 5 %)**, power
curves with confidence bands, minimum detectable effect, power vs n, heatmap over (A, n). A few hundred replicates per grid
point, justified by the Monte Carlo standard error √(p(1−p)/R). Fixed seed for every run. Include a negative control
(shuffled labels) and a sensitivity analysis. **Write down and freeze the analysis plan before looking at any power result.**

  (CIs, Monte Carlo error) next to every headline number.
